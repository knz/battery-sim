# Spec change requests

Whenever possible, it will be preferable to rewrite/simplify existing paragraphs -- we do not have users who know the previous version so there is no need to inform them of what has changed.

- [x] PV is optional
- [x] "regimes must never been mixed within one calculation" -> this only applies to pricing. For kWh usage and benefits of a battery, it's OK to mix pre-2027 and post-2027 data.
- [x] UX/wireframes and simulation structure: we want to clearly separate "energy savings" from "cost savings" in the results. The latter is optional. There should be a master checkbox "do you want to simulate cost savings as well". The UX items related to cost / billing / contracts should be hidden when cost simulation is disabled.
- [x] UX/wireframes: the data overview may need to show different granularities for different data series.
- [x] UX/wireframes: when adding a CSV file, the user should be prompted to indicate what data series the CSV is for
- [ ] UX/wireframes: the contract types should e just "dynamic", "fixed", "variable" (all are implicitely Dutch)
- [ ] UX wireframes: in various places, we'll want to mark a feature as "not implemented yet": UI control disabled / greyed out, but with a small button next to it that pops up a dialog that explains "this is not implemented yet, if you are interested please click the button below" with a "thumbs up" button. The button increments a corresponding feature counter in the database, as well as performs an asynchronous POST request to a configurable URL (failures ignored).
