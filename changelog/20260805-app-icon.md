# Placeholder app icon

> **Status:** complete, not committed — the user is committing the result themselves.

## 1. Task specification

The user's request, verbatim:

1. *"could you help define a placeholder icon for the app (we'll need one to package the app
   binary)"*
2. *"design: solar panel, energy bolt and battery / color: let's go for daisyUI primary /
   how far: full asset set"*

The icon is explicitly a **placeholder**: something to unblock packaging, not final artwork. It
should be replaceable without touching build scripts.

## 2. What the codebase already provides

Checked on `feat/pending-affordance-backend`:

- `packaging/build-appimage.sh:393` already carries the seam. It copies
  `packaging/battery-sim.png` into the AppDir if that file exists; otherwise it generates a
  256×256 solid-green PNG inline with a hand-written zlib/struct script, with the comment
  "Replace `packaging/battery-sim.png` when it does [have artwork]". So dropping a PNG at that
  path is the whole Linux integration — no script change is required for the AppImage to pick it
  up.
- `packaging/build-appimage.sh:381` writes the `.desktop` entry with `Icon=battery-sim`, matching
  the AppDir-root icon name appimagetool requires.
- **No favicon exists anywhere.** The four page templates (`workspaces.html`,
  `workspace_results.html`, `workspace_edit.html`, `workspace_data.html`) declare a `<title>` but
  no `<link rel="icon">`, so browsers show their default document glyph.
- The app's only committed brand colour is daisyUI's default `primary`, `#570df8` — it appears
  literally at `workspace_results.html:353` as the Plotly marker colour, and by token in
  `app/static/src/app.tailwind.css` (`.radio-card:has(input:checked)`, `.bench-fill`,
  `.bench-dot`, the active-tab underline). The existing placeholder green (`#166f3d`) matches
  nothing in the UI.

## 3. Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Motif | Solar panel, energy bolt, battery | User's choice. Names the three things the simulator reasons about: generation, flow, storage. |
| Colour | daisyUI `primary` `#570df8` | User's choice. The one colour already load-bearing in the UI, so icon and app agree. |
| Scope | Full asset set | User's choice. Master SVG + `packaging/battery-sim.png` + favicon wired into the templates. **Extended mid-task** — see §3.1. |
| Master format | SVG, hand-authored | It is the source the other formats derive from, and it is diffable. Replacing the placeholder means replacing one file and re-running one script. |
| PNG generation | A committed script, plus the PNG itself | The PNG is committed so the AppImage build needs no image toolchain (matching the build script's existing no-image-library stance), but it is reproducible from the SVG so the two cannot silently diverge. |

### Deliberately not done

- Changing `build-appimage.sh`'s inline-PNG fallback: it stays as the last-resort path if
  `packaging/battery-sim.png` is ever absent.

## 3.1 Requirements change — macOS and Windows icons added

`.icns` and `.ico` were initially deferred, on the reasoning that neither platform's packaging
exists yet and generating them would add a tooling dependency ahead of a consumer. After the first
round was delivered the user asked for them anyway: *"let's generate the windows/macOS icons as
well"*. The deferral is reversed; the artwork should not be what blocks either port when it starts.

The tooling objection turned out to be smaller than assumed. **Pillow** writes both containers, so
neither `iconutil` (macOS-only — the icns could not have been built on this Linux machine) nor a
system `icnsutils`/`png2icns` package is needed. Pillow is required *only* for the two containers;
the PNG targets still need a renderer alone, and that split is enforced in the code by importing
Pillow lazily inside `_require_pillow()`.

Each `.ico` member is rendered from the SVG at its own size and passed via `append_images`, rather
than letting Pillow downscale a single raster — at 16 and 24px the difference is visible. The
`.icns` is derived from one 1024px render, which is sufficient because Pillow's ICNS writer builds
the whole `ic07`..`ic14` chunk set from it.

## 3.2 Requirements change — icon shown in the top bar

Third user request: *"could we also display the icon left of the app title at the top bar"*.

**Scope question this raised, and how it was resolved.** The four screens do not share a header,
and only ONE of them shows the app title. `workspaces.html` (the list, the app's home screen) leads
its navbar with `Home Battery Simulator`; `workspace_results.html`, `workspace_data.html` and
`workspace_edit.html` instead lead with a `← Your analyses` back link, and the first two then show
the *analysis* title, not the app's. So "left of the app title at the top bar" identifies exactly
one place, and the icon went there only. Adding it to the other three would have put it beside a
back link, where it competes with that link's affordance and repeats a mark the user has just
clicked away from — a placement the user did not ask for and that the layout does not invite.

The icon is marked `alt=""` / `aria-hidden="true"`. It is decorative: the adjacent text already
names the app, so an accessible name here would be read as a duplicate of the title.

## 4. Files created / modified

### Created

- `packaging/icon/battery-sim.svg` — the master artwork. Hand-authored, 256 viewBox. A rounded
  `#570df8` plate carrying three elements on a diagonal: solar panel lower-left, battery lower-
  right, white bolt across the upper band. Flat fills only; no gradients, filters, or thin strokes.
- `packaging/icon/render.py` — SVG → PNG renderer. Tries cairosvg, then `rsvg-convert`, then
  `inkscape`; exits with install instructions if none is present. `--check` re-renders to a temp
  directory and diffs against the committed PNGs, exiting non-zero if they are stale — usable as a
  CI guard against an SVG edit whose PNGs were never regenerated.
- `packaging/battery-sim.png` (256×256) — the AppImage icon, at the path `build-appimage.sh`
  already probed.
- `packaging/battery-sim.icns` (113KB) — macOS bundle icon, chunks `ic07`–`ic14`.
- `packaging/battery-sim.ico` (18KB) — Windows icon, members at 16/24/32/48/64/128/256.
- `app/static/favicon.svg`, `app/static/favicon-32.png`, `app/static/favicon-180.png`.

### Modified

- `app/templates/workspaces.html`, `workspace_results.html`, `workspace_edit.html`,
  `workspace_data.html` — three `<link>` tags each (SVG icon, 32px PNG fallback, apple-touch-icon)
  above the existing stylesheet link. Four separate edits because the templates share no `<head>`
  partial.
- `app/templates/workspaces.html` (again) — the navbar's leading box now holds an `<img>` of
  `/static/favicon.svg` at `h-8 w-8` before the title span, and gained `flex … items-center
  gap-2.5`. See §5 for why `flex` is spelled out.
- `app/static/app.css` — **regenerated** via `npm run build:css`. Required, not incidental: see §5.
- `packaging/build-appimage.sh` — comment only, in the icon section: records that the committed
  PNG is generated from the SVG, and that the inline generator below it is now a last resort
  rather than the normal path. No behaviour change.

## 5. Obstacles

- **The first draft's bolt was broken.** It was authored as a path whose two halves met at
  `x=128` with a 2-unit seam between `y=126` and `y=128`; that rendered as a gap with the upper
  half visibly detached. Rewritten as a single closed path.
- **The first draft overlapped the bolt across the panel.** Legible at 256px, but at 32px the two
  merged into one indistinct mass. Fixed by moving the bolt into the empty upper band so no two
  elements overlap at all.
- **The battery's charge fill was invisible.** Drawn in the same `#a58bfa` as the body around it,
  so the state-of-charge reading — the point of drawing a partial fill — was lost. Changed to
  white, which also ties it to the bolt.
- **No SVG renderer on the machine.** cairosvg was absent, `rsvg-convert` and `inkscape` not on
  PATH, and only ImageMagick's `convert` was available. Installed cairosvg into a throwaway venv
  outside the repo for the render/inspect loop; the repo gained no dependency, since the PNGs are
  committed.
- **The header icon first rendered ABOVE the title, not beside it.** The container computed to
  `display: block`, which left `items-center` and `gap-2.5` inert. The cause is that `flex-1` sets
  `flex-grow` on the box *as a child of* the navbar; it does not make the box a flex container
  itself. The original markup never needed one because it held a single `<span>`. Fixed by adding
  an explicit `flex`, verified by reading `getComputedStyle` back (`block` → `flex`) rather than by
  eye. The template carries a comment so the class is not tidied away later.
- **Two of the new utility classes were missing from the compiled CSS.** `h-8` and `w-8` had never
  appeared in any template, so Tailwind had never emitted them, and the icon rendered unsized.
  `app/static/app.css` is a committed build artefact, so it had to be regenerated with
  `npm run build:css` — a step easy to miss, since the template change alone looks self-contained.

## 6. Verification

- `packaging/icon/render.py --check` → "icons up to date", exit 0, with the two containers
  included in the comparison.
- **Output is deterministic**: rendering twice produced byte-identical `.icns` and `.ico`
  (md5 unchanged). This matters because a non-deterministic writer would make `--check` fail
  spuriously in CI.
- All three static files served by the app: `/static/favicon.svg` 200 `image/svg+xml`,
  `/static/favicon-32.png` 200 `image/png`, `/static/favicon-180.png` 200 `image/png`; the link is
  present in the rendered HTML of `/`.
- Full suite: **1341 passed, 24 skipped** in 102s — the skip count matches the existing baseline
  (the live-HA suite). Run after the template edits; **not re-run** after the `.icns`/`.ico` work,
  at the user's direction, since that step added only generated binaries and changes to a
  standalone dev script that no test or runtime path imports.
- `.icns` structure parsed by hand: correct `icns` magic, declared length matches actual (113408),
  TOC present, chunk set `ic07`–`ic14` (16px through 1024px retina).
- `.ico` structure: all seven declared sizes present. Each member was decoded and sampled — plate
  centre reads exactly `(87, 13, 248)` = `#570df8`, corner reads fully transparent, confirming
  real artwork rather than blank or mis-sized entries.
- The rendered PNG was inspected visually at 256, 48, 32 and 16px; the `.ico` members at 32, 48
  and 256; the `.icns` at 1024.
- **Header placement**: screenshotted with Playwright against a live server, before and after the
  `flex` fix, and confirmed by reading the container's computed `display`/`alignItems` back from
  the DOM. Final state: icon left of the title, vertically centred.
- After the header change: `pytest -k "workspaces or list or smoke or i18n"` → **217 passed,
  1 skipped**, 1147 deselected. The full suite was not re-run, at the user's direction.

### Known limitation

At **16px** the mark degrades to a soft blob: the bolt and battery remain faintly separable but
the panel's cells dissolve. This is inherent to a three-element composition at that size, and was
accepted rather than designed around, since the artwork is a placeholder. A final icon would want
either a simplified 16px variant or a single-element mark.
