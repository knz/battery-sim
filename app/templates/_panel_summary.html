{# _panel_summary.html — the data summary band (specs/02-ux-wireframes.md §2.3a "The data summary band — Your data at a glance"). An UNNUMBERED band between panel ① and panel ②, modelled on the setup band: always expanded, never collapses, no CTA, no [?] affordance, no focus state (state machine §3.4). Unlike the setup band it has nothing to summarise until data exists, so index.html includes it only when `data_summary` is present — i.e. from DATA_READY onward (§3.1). It drives no transition; panel ①'s own "Next: parameters →" CTA still steps from ① to ②. Everything here follows from the household's OWN recorded data before any SIMULATED battery, policy or pricing (§6.11 energy row minus efc, over the §6.3 load reconstruction). None of it needs the battery the user is about to describe in panel ②. The spot-price rows are battery-free for the same reason the charge/discharge bands are: the price series is an input, not a cost model (§1.4). The EXISTING (measured) battery vs. the SIMULATED (panel ②) battery: if the household already owns a battery, its charge/discharge sensors are mapped (§4.1) and §6.3 reconstructs load by stripping it, so the household-consumption and self-consumption figures are net of that battery. When `data_summary.battery` is present this band renders its measured throughput as its own group and labels the Household/Solar rows "net of your existing battery"; when absent, both the group and the qualifier drop out (omit, never zero — §2.4). Omit-don't-zero (§2.4): each optional group renders only when its inputs are present — `data_summary.solar` (PV), `data_summary.battery` (existing battery), `data_summary.price` (spot price). Rendering 0 kWh / 0% would assert something the data cannot support. View-model shape (app/sample_data.py `_data_summary`, computed in app/summary_view.py): data_summary = { coverage: str, days: int, grid: {imported, exported}, # always household: {consumption, self_sufficiency, # str, or None when reconstruction net_battery: bool, # is unreliable (both hidden) self_sufficiency_clamped: bool}, # neg. clamped to 0% → caveat solar: {produced, self_consumption?, # PV present (self_consumption omitted coverage, days, partial: bool} | None, # if nothing produced); partial→span battery: {charged, discharged} | None, # existing battery present price: {avg, min, max} | None, # spot price present notes: [{key, ...params}], # data-quality caveats (may be empty) } Each DERIVED metric (Consumption, Self-sufficiency, Self-consumption) carries an ⓘ .slot-info-btn that opens the shared #slot-info-dialog (defined in _panel_data.html, wired by the delegated handler in ha_fetch.js) with a plain-language explanation of its formula. The raw measured sums (grid import/export, price) carry no ⓘ. The Consumption blurb varies with the existing-battery case, since §6.3 then strips that battery from the reconstruction. UI chrome is wrapped in _() for translation (English/Dutch); data values (numbers, coverage strings) stay literal. #}
