{# _footer.html — the site footer, included at the bottom of every screen. Two lines and one dialog: 1. the privacy statement — the app runs locally and nothing leaves the machine; 2. the attribution/licence line, carrying four interactive pieces: the author's site, the NO WARRANTY button, the licence, and the source repository; 3. the warranty dialog that the NO WARRANTY button opens. There is no base template in this codebase — every screen is a standalone full page — so this partial is `{% include %}`d by each of the four (workspaces, workspace_edit, workspace_data, workspace_results), the same way `_workspace_card.html` and the panels are reused. Adding a screen means adding the include; there is nowhere central that would do it automatically. **The attribution line is ONE msgid with holes, not six concatenated chunks.** It carries four links/buttons, so the naive spelling breaks the sentence into fragments and lets the markup fall between them. That hands translators word-salad and makes Dutch word order impossible to honour — Dutch does not put "Licensed as X" where English does. Instead the whole sentence is a single translatable string with `%(name)s` holes, and the anchors are substituted in afterwards. The escaping is `_msg.html`'s: `_( ... ) | e | interpolate(...) | safe`. Piping the translated string through `e` first makes it a `Markup`, and `Markup.__mod__` escapes each substituted value EXACTLY once — so the `Markup(...)` anchors built below pass through as markup while any plain string would still be escaped. `| safe` then stops the surrounding `{{ }}` escaping the assembled result a second time. Do not "simplify" this to a bare `interpolate` (the anchors would render as visible `` text) or drop the `| e` (the sentence's own characters would go unescaped). The app name is deliberately the same msgid as the `` and the header — one string, one translation, so the three cannot drift. **The dialog is page-level**, for the reason the other dialogs on these screens already document: a `<dialog>` inside a subtree daisyUI gives `content-visibility: hidden` still enters the top layer on `showModal()` — blocking every click on the page — but is never painted. Being inside `<footer>` is safe today, but the dialog lives as a sibling of it rather than inside the text it belongs to, matching `#slot-info-dialog` and `#pending-dialog`. The dialog states what AGPL §15 and §16 actually disclaim, in prose, and links to the full LICENSE rather than claiming to replace it. It also names the risk specific to THIS program, which the generic clause does not: the figures are retrospective estimates computed from the user's own data under an assumed future tariff regime, not advice to buy anything. #} {# The four substituted pieces.
