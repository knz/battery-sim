It was written as a shared macro in phase 4.1, when panel ① and the new screen drew the same two questions from one copy; phase 4.2 deleted panel ① (§2′.6 folded what was left of the three-panel page into the results screen), so the second call site and the `titled=False` branch it needed both went with it. Renaming them to `setup.has_pv` would silently enlist them into panel ②'s form and into `parse_form`'s section-gated branch, which is a different commit point with different semantics. Both re-gate the slot roster IMMEDIATELY and client-side (ha_fetch.js `applySetupGating`, keyed on these exact two names), so the user sees which series are being asked for as they answer. The server computes the initial hidden state, so the first paint is right with JS off. §2′.5's box chrome — the heading and the card border — is unconditional now: "an untitled pair of questions above a table reads as chrome; the box names what they are for".
