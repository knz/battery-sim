## 3. System libraries bundled in the Linux AppImage

**This section applies to the Linux AppImage only.** The macOS and Windows bundles use
the platform's own web view and carry none of these libraries, and neither does running
from source.

**This section is a snapshot, not a machine-checked derivation.** Sections 1 and 2 above
are regenerated from files in this repository and CI verifies they are current. This one
cannot be: the libraries exist only on the Ubuntu build host, and identifying them needs
`dpkg` and a built AppDir. It is refreshed by running the generator with
`--refresh-system-libs` on that host, which writes
`packaging/appimage-system-libraries.json`; the freshness check cannot tell whether that
file still matches the host.

To give a native window on a machine with nothing installed,
`packaging/build-appimage.sh` copies the GTK 3 / WebKit2GTK stack off the build host. It
starts from six roots — libwebkit2gtk-4.1, libjavascriptcoregtk-4.1, libgtk-3, libgdk-3,
libgirepository-1.0 and PyGObject's `_gi` extension, plus the plugin modules under
`gdk-pixbuf-2.0/`, `gio/modules/` and `webkit2gtk-4.1/` — and follows their transitive
`ldd` closure.

As measured on the build host, that comes to **119 shared libraries from 85 Ubuntu 24.04
(noble) source packages**, listed below.

Libraries the image deliberately leaves to the user's machine are not bundled and are not
listed: the C library and dynamic loader, libstdc++, libgcc_s, the GL/EGL/DRI stack and
the X11/Wayland client libraries. They must match the user's kernel, graphics driver and
display server rather than the build host's. (`HOST_PROVIDED` in
`packaging/check-appdir-closure.py` is the authoritative list.)

### Licensing and how to exercise your rights

Of the 85 source packages below, 38 are under the GNU Lesser General Public License —
version 2.0 or 2.1, or the LGPL-3-or-GPL-2 form. The LGPL is compatible with this
application's AGPL-3.0-only licence, so bundling them is permitted; what the LGPL
additionally requires is that you be told they are there, that you can obtain their source,
and that you can replace them. The rest of this subsection is that.

**Licence texts.** Verbatim copies are in `licenses/` in this repository and are
distributed with the AppImage:

- LGPL-2.1 — `licenses/LGPL-2.1.txt`
- LGPL-3 — `licenses/LGPL-3.txt`
- GPL-2 — `licenses/GPL-2.txt`
- GPL-3 — `licenses/GPL-3.txt`

Both GPL texts are present because LGPL-3 §4(b) requires the GNU GPL to accompany the
LGPL, and because several bundled libraries (Nettle, GMP, libunistring, libidn2) are
offered under "LGPL-3-or-later or GPL-2-or-later", making GPL-2 a licence you may
actually choose.

**Obtaining the source.** Release AppImages are built on `ubuntu-24.04`, pinned in
`.github/workflows/release.yml`. Every library below is the stock Ubuntu 24.04 (noble)
build of the source package and version named in the table, so those two strings identify
the exact code inside the binary. Three routes to it:

1. On an Ubuntu 24.04 system, `apt-get source <source-package>=<version>`.
2. From Ubuntu's published archive at https://archive.ubuntu.com/ubuntu/pool/ .
3. By written request through https://raphaelposs.com/contact/, for as long as
   the corresponding release is offered.

The LGPL-2.1 §6(b) option — relying on a copy of the library already installed on your
machine — is not applicable here, since an AppImage exists precisely to carry its own.
The route above is the §6(d) equivalent-access one: the source is offered from the same
place the binary is, at no greater cost.

**Relinking and replacing a library.** The libraries are dynamically linked, and are
plain `.so` files inside the image, so substituting your own build requires no rebuild of
this application:

```
./Home-Battery-Simulator-x86_64.AppImage --appimage-extract
cp your-libfoo.so.1 squashfs-root/usr/lib/x86_64-linux-gnu/
./squashfs-root/AppRun
```

**Modified libraries.** One bundled library is not a verbatim copy of the Ubuntu binary,
and LGPL §6(a) asks for the corresponding source including the changes made, so it is
stated here rather than left to be found:

- `libwebkit2gtk-4.1.so.0` — Two NUL-terminated path strings in .rodata are rewritten in place,
  replacing the compiled-in helper-process directory `/usr/lib/x86_64-linux-gnu/webkit2gtk-4.1`
  with `/tmp/.battery-sim-webkit`, a symlink AppRun points at the mounted image. No code is
  changed and no byte offset moves (the replacement is NUL-padded to the original length). The
  patching code is `packaging/build-appimage.sh` (the "repointing WebKit's helper path" step),
  published with this project under the AGPL-3.0-only.

Every other library is copied byte-for-byte from the Ubuntu package named in the table.
